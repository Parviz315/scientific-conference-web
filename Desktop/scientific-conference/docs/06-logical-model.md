# Логическая модель базы данных: Ташкили Конфронсии илмӣ

## 1. Итоговая логическая модель (Таблицы и связи)

| Таблица | Назначение | Ключи и связи |
| :--- | :--- | :--- |
| **users** | Справочник пользователей системы | PK `id`; UQ `username`, `email`; роли: admin, organizer, reviewer, participant |
| **sections** | Секции / направления конференции | PK `id`; название и время проведения |
| **submissions** | Заявки и научные доклады | PK `id`; FK `user_id` → users, `section_id` → sections; статусы: pending, under_review, approved, rejected |
| **reviews** | Тақризҳо (рецензии) на доклады | PK `id`; FK `submission_id` → submissions, `reviewer_id` → users |
| **notifications** | Система уведомлений пользователей | PK `id`; FK `user_id` → users |

---

## 2. Правила целостности (Integrity Rules)
1. Уникальность почты и имени пользователя в таблице `users`.
2. Статус заявки (`submissions.status`) изменяется строго по алгоритму: `pending` → `under_review` → `approved` / `rejected`.
3. Каждая рецензия (`reviews`) должна быть привязана к конкретной заявке и проверяющему рецензенту.
4. Каскадное ограничение: при удалении пользователя связанные заявки или уведомления обрабатываются через `ON DELETE RESTRICT` или `CASCADE` (в зависимости от роли).

## 3. Нормализация «плоской» таблицы до ЗНФ

### Исходная ненормализованная таблица («плоская» `conference_flat`)
Содержала данные об авторах, их докладах, секциях и рецензиях в одной таблице, что вызывало дублирование и аномалии.

* **Функциональные зависимости:**
  * `submission_id` → `title`, `abstract`, `section_name`, `author_name`
  * `section_name` → `room`
  * `reviewer_id` → `reviewer_name`

### Шаг 1. Первая нормальная форма (1НФ)
* Устранены повторяющиеся группы и списки. Все поля содержат атомарные значения.
* Первичный ключ стал составным (например, `submission_id` + `reviewer_id`, если доклады оцениваются несколькими лицами).

### Шаг 2. Вторая нормальная форма (2НФ)
* Таблица переведена в 1НФ. Устранены частичные зависимости неключевых атрибутов от составного ключа. 
* Данные о секциях и авторах вынесены в отдельные таблицы (`sections`, `users`).

### Шаг 3. Третья нормальная форма (3НФ)
* Устранены транзитивные зависимости (когда неключевой атрибут зависит от другого неключевого атрибута).
* **Результат:** Получена чистая реляционная структура из 5 взаимосвязанных таблиц (`users`, `sections`, `submissions`, `reviews`, `notifications`), полностью лишённая аномалий обновления, вставки и удаления.
